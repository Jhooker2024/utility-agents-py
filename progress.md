## Decisions

- Modules mirror the Elixir ones. `request_path.py` is `lib/utility_agents.ex`; `model.py` is
  `anthropic.ex`; `tools.py` holds the five tools; `tool_text.py` is `tools/text.ex`;
  `text.py` holds the date, month and number wording that Elixir kept in `Presenter`.
- Settings are in `src/utility_agents/config.yml`.
- A check result is `None` when it passes and the reason as text when it fails.
- A tool that cannot do what was asked raises `ToolError`; its text goes back to the model.
- Tool schemas are generated from the Pydantic models by `schema.py`, in the exact shape the
  Elixir version sent. Structured answers go through `with_structured_output(...,
  method="json_schema")` with a Pydantic model.
- Retries are ours, not the SDK's: the SDK also retries a reply timeout and a 504, which could
  bill a request twice.

## Differences from the Elixir version, on purpose

- The Anthropic SDK inside LangChain drops `"type"` next to `"enum"` in an output schema. The
  golden test applies that one rule to the recording's `output_config` before comparing.
- A structured answer is validated with Pydantic, so an answer missing a field is unreadable.
  Elixir accepted `{"sensible": true}` without a reason.
- An API error body is printed as JSON, not as an Elixir map.
- Text of only spaces counts as no value in a proposal. Elixir did that for the empty string
  only.
